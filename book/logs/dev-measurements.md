# Development measurements

One-off measurements recorded during the build session on the machine
in `train-cyberpunk-5000.log` (AMD Threadripper PRO 9975WX, 32 cores /
64 threads, gcc 13.3.0). They are not regenerated by `make check`; they
document the engineering decisions the book narrates. The commands show
the measured workloads, with their checkpoint destinations updated to
a writable regular path for the current atomic-save code. Generated
text, timings, and hardware-dependent defaults can vary. The measured
training executables used the opt-in `make NATIVE=1` host tuning; plain
`make` no longer adds `-march=native`.

## Corpus generation (Ollama, dolphin3)

Single-call timing (`time bash scripts/gen-corpus.sh` at TARGET_BYTES=500):

    single call: 2.329s, 1685 bytes

Full run (final progress lines of `bash scripts/gen-corpus.sh`):

    gen-corpus: 1191801 / 1200000 bytes after 775 calls
    gen-corpus: 1200020 / 1200000 bytes after 780 calls
    gen-corpus: done, 1200020 bytes in data/cyberpunk.raw.txt after 780 calls

That block is the historical generation capture. The committed raw
artifact is exactly 1,200,000 bytes, so running the generator against
the current snapshot at its default target makes zero additional calls.

Cleaning (`bash scripts/clean-corpus.sh`):

    clean-corpus: 1096793 bytes -> data/cyberpunk.txt
    clean-corpus: vocabulary of 80 distinct characters
    clean-corpus: 2127 transmission header lines

The cleaner was later tightened to retain only headers followed by at
least one valid dialogue line and to enforce the generator's sector and
punctuation grammar. One later local cleaning run produced:

    clean-corpus: 1089394 bytes -> data/cyberpunk.txt
    clean-corpus: vocabulary of 80 distinct characters
    clean-corpus: 2011 transmission headers

## Thread-count sweep, default model, BEFORE -ffast-math

`OMP_NUM_THREADS=$n ./tiny-agenc train --data data/shakespeare.txt --steps 50 --out build/measurement.bin`

    threads=8  -> 388.9 ms/step
    threads=16 -> 304.3 ms/step
    threads=32 -> 268.2 ms/step
    threads=64 -> 501.5 ms/step

## Same sweep AFTER adding -ffast-math to CFLAGS

    threads=16 ->  59.6 ms/step
    threads=32 ->  43.3 ms/step     <- the shipped default (one per physical core)
    threads=64 -> 225.7 ms/step     <- SMT contention + fork/join overhead

-ffast-math speedup at 32 threads: 268.2 / 43.3 = 6.2x.

## Tiny-workload thread sweep (2 layers, width 64, block 32, batch 8)

Before the `PARALLEL_THRESHOLD` guard existed:

    threads=1  ->  13.0 ms/step
    threads=4  ->   5.9 ms/step
    threads=16 ->   4.7 ms/step
    threads=64 -> 191.7 ms/step     <- 40.8x slower than 16 threads

The printed loss at step 100 was the same (2.5174) at every tested
thread count. The parallel loops partition disjoint output work.

## Training memory (default model, 10 steps)

`/usr/bin/time -v ./tiny-agenc train --data data/cyberpunk.txt --steps 10 --out build/measurement.bin`

    Maximum resident set size (kbytes): 388580

Computed allocation: values arena 47,915,008 floats (182.8 MiB),
gradient arena 47,513,600 floats (181.2 MiB), and four 815,360-float
parameter buffers (12.4 MiB), for 376.5 MiB total. The measured peak
was 388,580 kB RSS, or 379.5 MiB.
